# Experiment 1：手写 LRU Cache

> 语言：Go · 建议时长：60～90 分钟 · 规模：核心实现与测试总计不超过 500 行

## 题目

实现一个固定容量的 LRU（Least Recently Used，最近最少使用）缓存。

当容量大于 `0` 且缓存已满时，写入新键需要淘汰最久没有被使用的键。一次成功的读取，或一次写入，都视为该键刚刚被使用。

请将代码放在当前目录的 `code` 子目录中。只需实现内存版本，不需要持久化，也不要求并发安全。

## API

使用下面的公开接口；内部数据结构由你自行设计。

```go
package lru

type Cache struct {
	// 自行设计
}

// New 创建一个最多容纳 capacity 个键的缓存。
// capacity 保证大于等于 0；负数容量不在本题输入范围内。
func New(capacity int) *Cache

// Get 返回键对应的值以及该键是否存在。
func (c *Cache) Get(key int) (value int, ok bool)

// Put 写入或更新一个键值对。
func (c *Cache) Put(key, value int)

// Len 返回当前缓存中的键数量。
func (c *Cache) Len() int
```

## 行为规则

1. `Get` 命中时，返回对应值，并将该键标记为最近使用。
2. `Get` 未命中时，返回 `0, false`，且不能改变其他键的新旧顺序。
3. `Put` 写入已有键时，更新它的值，并将该键标记为最近使用；缓存长度不变。
4. 当容量大于 `0` 时，`Put` 写入新键：

   - 缓存未满：直接加入；
   - 缓存已满：先淘汰最近最少使用的键，再加入新键。

5. 容量为 `0` 时，所有 `Put` 都是无操作，所有 `Get` 都未命中，`Len` 始终为 `0`。
6. `Len` 只读取当前长度，不能改变任何键的使用顺序。
7. 任意时刻，缓存中的键不能重复，且 `Len()` 不能大于容量。

## 复杂度要求

- `Get`：平均时间复杂度 `O(1)`
- `Put`：平均时间复杂度 `O(1)`
- `Len`：时间复杂度 `O(1)`
- 空间复杂度：`O(capacity)`

不得使用第三方缓存实现，也不得使用标准库的 `container/list`；缓存和顺序维护逻辑需要自己完成。

## 示例

下面的“顺序”仅用于说明行为，按“最近使用 → 最久未使用”排列：

| 操作 | 返回值 | 操作后的顺序 | 说明 |
| --- | --- | --- | --- |
| `c := New(2)` | - | `[]` | 创建容量为 2 的缓存 |
| `c.Put(1, 10)` | - | `[1]` | 写入键 1 |
| `c.Put(2, 20)` | - | `[2, 1]` | 键 2 最近被使用 |
| `c.Get(1)` | `10, true` | `[1, 2]` | 读取使键 1 变为最近使用 |
| `c.Put(3, 30)` | - | `[3, 1]` | 淘汰键 2 |
| `c.Get(2)` | `0, false` | `[3, 1]` | 未命中，不改变顺序 |
| `c.Put(1, 11)` | - | `[1, 3]` | 更新键 1 的值和顺序 |
| `c.Put(4, 40)` | - | `[4, 1]` | 淘汰键 3 |

## 验收标准

至少编写单元测试覆盖以下场景：

- 基本的写入、读取与未命中；
- `Get` 命中后会刷新使用顺序；
- 更新已有键会更新值和使用顺序，但不会增加长度；
- 缓存满时淘汰正确的键；
- 容量为 `0` 和容量为 `1`；
- 键或值为 `0`、负数时仍能正确区分“存在”和“不存在”；
- 连续执行多轮读写后，缓存长度始终不超过容量。

建议至少提交 `code/lru.go` 和 `code/lru_test.go`。仓库目前尚未初始化 Go module，你可以自行选择在仓库根目录或 `code` 目录初始化；从所选 module 根目录运行 `go test ./...` 应当通过。

完成条件：代码经过 `gofmt`，测试通过，并能说明你的实现为什么满足上述时间复杂度，以及维护了哪些关键不变量。
