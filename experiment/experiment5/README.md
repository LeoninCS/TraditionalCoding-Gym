# Experiment 5：实现一个简易版 WaitGroup

> 类型：并发同步工具 · 语言：Go 1.22+ · 难度：入门进阶 · 建议时长：60～90 分钟
> 规模：核心实现约 40～80 行，连同临时验证以 500 行以内为参考，不按行数验收。

实现一个简易版 WaitGroup：登记任务数量，任务完成时减一，等待者在计数归零后继续执行。重点练习共享计数和唤醒多个等待者。

基础版只实现 `Add`、`Done`、`Wait`，不要求 `Go` 方法、超时、取消或检测所有错误调用顺序。

## 接口

```go
package miniwg

type WaitGroup struct {
    // 内部结构自行设计
}

func (wg *WaitGroup) Add(delta int)
func (wg *WaitGroup) Done()
func (wg *WaitGroup) Wait()
```

- `var wg WaitGroup` 可以直接使用；不要求 nil 接收者可用，使用后不要复制实例。
- `delta` 范围为 -100,000～100,000；合法操作后的计数不超过 100,000，更大的计数和整数溢出不要求处理。
- 最多同时有 10,000 个调用，每个实例最多复用 1,000 轮。公共接口保持不变。
- 从零增加计数必须在启动本轮 `Wait` 调用之前完成；计数大于零时，可以并发增加、减少计数和等待。
- 开始下一轮前，必须等上一轮所有 `Wait` 都返回。违反这两项调用顺序的情况不要求处理。

## 要求

1. **REQ-01 初始状态**：零值实例的计数为 0；此时 `Wait` 直接返回。`Add(0)` 不改变状态。
2. **REQ-02 修改计数**：`Add(delta)` 将计数增加 `delta`；`Done()` 等价于 `Add(-1)`。它们不等待其他任务完成。
3. **REQ-03 等待归零**：计数大于 0 时，`Wait` 必须等待；计数归零后，本轮所有等待者都能返回，不能只唤醒一个。
4. **REQ-04 非法减计数**：如果一次操作会使计数变成负数，必须在调用者所在的 goroutine 中 panic，不约束文案；计数保持操作前的值，recover 后实例仍可使用。
5. **REQ-05 并发与可见性**：合法调用顺序下没有数据竞争。任务在减少计数前完成的写入，必须在本轮 `Wait` 返回后对等待者可见。
6. **REQ-06 复用与隔离**：遵守调用顺序时，同一个实例可反复登记、完成和等待任务；不同实例的计数与等待互不影响。

本题的非法减计数规则是简化约定，不要求完全复制标准库对误用的处理。等待者之间不要求固定返回顺序，也不要求公平排队。

## 实现约束

- **CHECK-01**：只用标准库，禁止使用或包装 `sync.WaitGroup`。可以使用其他标准库同步工具或内置 channel。通过源码检查验收。
- **CHECK-02**：等待必须使用同步机制，禁止忙等和 `time.Sleep` 轮询；合法调用最终归零后，不得遗留永久等待的 goroutine。通过 Review 和竞态检测检查。
- **CHECK-03**：不触发归零的计数更新和一次等待登记开销为 `O(1)`；归零时唤醒 `m` 个等待者的总开销为 `O(m)`，无等待者时为 `O(1)`。额外空间为 `O(m+1)`，不累计保留历史轮次；阻塞和调度时间另计。通过源码说明和 Review 检查。

## 示例

以下是同一实例的一轮操作，计数只用于解释，不要求提供查询接口：

| 操作 | 结果 |
| --- | --- |
| 创建零值实例，然后 `Add(2)` | 计数为 2，调用返回 |
| 两个 goroutine 分别调用 `Wait()` | 两个调用都等待 |
| 一个任务完成，调用 `Done()` | 计数变成 1，等待者仍不能返回 |
| 另一个任务完成，调用 `Done()` | 计数变成 0，两个等待者都能返回 |
| 等这两个 `Wait` 都返回，再 `Add(1)` | 开始新一轮 |
| 本轮任务调用 `Done()` 后，再调用 `Wait()` | 直接返回 |

如果计数为 1 时调用 `Add(-2)`，该调用 panic；recover 后再执行 `Done()`，计数才归零。

## 验证要点

以下场景均需验证；只使用公开接口，临时测试文件不提交到仓库。

| 场景 | 对应要求 | 操作与期望 |
| --- | --- | --- |
| TC-01 零值与零增量 | REQ-01 | 零值实例的 Wait 可直接返回；计数为 0 或 1 时 Add(0) 均不改变后续等待结果 |
| TC-02 批量计数 | REQ-02、03 | Add(3)，再 Done 和 Add(-2)，随后 Wait 返回；另验证 Add(100000) 后 Add(-100000) 可归零 |
| TC-03 多等待者 | REQ-02、03 | Add(2) 后发起多个 Wait；一次 Done 不足以结束等待，第二次 Done 后所有 Wait 均能返回 |
| TC-04 非法减少 | REQ-04 | 零值 Done 必须 panic；计数为 1 时 Add(-2) 必须 panic。分别 recover 后，前者仍能直接 Wait，后者需 Done 后才能结束等待 |
| TC-05 并发与可见性 | REQ-02、03、05 | 预先登记任务，各 goroutine 写入各自独占的结果位置后 Done；Wait 返回后读取全部结果，无遗漏且竞态检测无报告。另保持一个未完成任务，期间并发 Add、Done，最后归零 |
| TC-06 重复使用 | REQ-01～03、06 | 按约定连续运行多轮，每轮登记和完成数量不同，等所有等待者返回后再开始下一轮；结果不能混入其他轮次 |
| TC-07 实例隔离 | REQ-03、06 | A 保持计数 1 时，B 可完成登记、归零和等待；随后完成 A，两者均能结束 |

并发验证使用同步信号和宽松超时，失败时也要尽力完成剩余任务。不要用固定 `Sleep` 猜测调度，也不要把“goroutine 已启动”当成“已进入 Wait”；TC-03、04 的阻塞条件和唤醒逻辑结合压力验证与代码 Review 检查。不要从私有计数推断结果。
