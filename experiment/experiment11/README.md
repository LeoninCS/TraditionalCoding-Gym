# Experiment 11：Top K 高频元素

> 类型：算法函数 · 语言：Go 1.22+ · 难度：入门进阶 · 建议时长：45～60 分钟
> 规模：核心实现约 30～80 行，连同临时验证以 500 行以内为参考，不按行数验收。

给定一个整数切片，返回出现次数最多的前 k 个不同整数。重点练习频次统计和排序规则。

基础版处理完整的输入切片，不要求流式输入、并行统计或返回每个数的出现次数。

## 接口

```go
package topk

func TopKFrequent(nums []int, k int) []int
```

- `nums` 长度为 0～100,000，允许 nil、重复值、0、负数和平台 int 边界值。
- `k` 表示最多返回几个不同整数，可以为任意非负 int；负数按 REQ-03 处理。
- 调用期间，调用者不修改输入。公共接口保持不变。

## 要求

1. **REQ-01 统计**：频次就是一个整数在 nums 中出现的总次数；同一个整数在结果中最多出现一次。
2. **REQ-02 选择与排序**：频次高的排在前面；频次相同时，数值小的排在前面。按这个顺序返回前 `min(k, m)` 个整数，m 是输入中不同整数的数量。
3. **REQ-03 边界**：`k < 0` 时先 panic，不约束文案，即使 nums 为空也一样。合法 k 下，输入为空或 `k == 0` 时返回 nil；`k > m` 时返回全部 m 个不同整数，仍按 REQ-02 排序。
4. **REQ-04 数据独立**：不能修改输入的内容或顺序。非空结果不能与输入或其他调用的结果共享可写存储；后续调用、修改输入或修改某次结果，不影响其他结果。

例如，某个数第一次出现得更早，不代表它在同频时排得更前；同频只比较数值大小。

## 实现约束

- **CHECK-01**：只用标准库，可以使用标准排序或容器工具，不限定具体算法。通过源码检查验收。
- **CHECK-02**：设 n 为输入长度、m 为不同整数的数量。非空输入且 `k > 0` 时，平均时间不超过 `O(n + m log(m+1))`，额外空间为 `O(m)`，不计输入与返回结果。通过源码注释和代码 Review 检查，不用苛刻耗时阈值验收。

## 示例

| nums | k | 返回结果 | 原因 |
| --- | --- | --- | --- |
| `[1, 1, 1, 2, 2, 3]` | 2 | `[1, 2]` | 1 出现 3 次，2 出现 2 次 |
| `[4, 4, 1, 1, 2]` | 1 | `[1]` | 1 和 4 都出现 2 次，选较小的 1 |
| `[-1, -1, 2, 2, 0]` | 5 | `[-1, 2, 0]` | 只有 3 个不同整数，全部返回 |
| `[3, 2, 1]` | 2 | `[1, 2]` | 频次相同，按数值升序 |
| `[1, 1]` | 0 | `nil` | 不需要返回元素 |
| `nil` | 3 | `nil` | 输入为空 |

## 验证要点

以下场景均为必测；只使用公开接口，测试文件放在仓库外的临时副本中。

| 场景 | 对应要求 | 操作与期望 |
| --- | --- | --- |
| TC-01 基本选择 | REQ-01、02 | 按全部正常示例验证；`[7]`、k=1 返回 `[7]`；`[7,7,7]`、k=2 仍只返回 `[7]` |
| TC-02 同频与截断 | REQ-01、02 | `[4,4,1,1,2,2]`、k=2 返回 `[1,2]`；改变输入排列但保持频次，结果仍相同；比较完整顺序，不能只比较集合 |
| TC-03 k 与空输入 | REQ-03 | nil 和非 nil 空切片在 k=0、1 时均返回 nil；非空输入 k=0 返回 nil；空和非空输入 k=-1 均 panic；`[2,1,2]` 在 k=2、3 和平台最大 int 时均返回 `[2,1]` |
| TC-04 数值边界 | REQ-01、02 | 输入为 `[最大int, 0, 最小int, 0, -1, -1]`，k=4，返回 `[-1,0,最小int,最大int]`；不能因比较数值时溢出而排序错误 |
| TC-05 输入与结果隔离 | REQ-04 | 保存输入副本，调用后逐项确认未变；分别修改返回值和原输入，确认互不影响。保存一次结果后再次调用，确认旧结果不变；修改其中一次结果不影响另一次 |
| TC-06 规模 | REQ-01～03 | 输入为 0～99,999 各一次，k=3 返回 `[0,1,2]`，k=100,000 返回全部数值的升序；100,000 个 7 在 k=10 时返回 `[7]` |

断言同时检查结果长度、内容和顺序；空结果要检查确实为 nil。复杂度与数据独立性还需代码 Review，不能只以“不报错”作为通过标准。
