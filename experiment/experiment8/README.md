# Experiment 8：简易令牌桶限流器

> 类型：并发组件 · 语言：Go 1.22+ · 难度：入门进阶 · 建议时长：60～90 分钟
> 规模：核心实现约 40～80 行，连同临时验证以 500 行以内为参考，不按行数验收。

实现一个限流器：桶里有令牌时允许请求通过，每次消耗一枚；令牌随时间补充，但不能超过桶的容量。重点练习时间计算和并发安全。

基础版只提供立即判断的 `Allow`；不要求等待令牌、预约、按 key 分组、动态修改配置或分布式限流。

## 接口

```go
package ratelimit

import "time"

type Limiter struct {
    // 内部结构自行设计
}

func New(rate int, burst int, now func() time.Time) *Limiter
func (l *Limiter) Allow() bool
```

- `rate` 表示每秒补充多少枚令牌，`burst` 表示最多保存多少枚；合法范围均为 1～10,000，更大的参数不要求处理。
- `now` 提供当前时间；nil 表示使用 `time.Now`。注入时钟由调用者保证并发安全、时间不回退，且快速返回、不 panic、不回调同一实例。
- 时间差不超过 24 小时，累计调用最多 100,000 次；实例通过 `New` 创建，不要求零值或 nil 接收者可用，不要复制实例。公共接口保持不变。

## 要求

1. **REQ-01 创建**：`rate <= 0` 或 `burst <= 0` 时 panic，不约束文案；合法参数创建的桶初始有 burst 枚令牌，nil 时钟参数可用。
2. **REQ-02 持续补充**：从创建开始，令牌按 rate 枚/秒的速度连续增加，最多为 burst。不足一枚的额度也必须累计；例如 rate 为 2 时，经过 250 毫秒增加半枚。满桶后多余的额度丢弃，不能留给后续请求使用。
3. **REQ-03 允许或拒绝**：`Allow` 根据本次读取的当前时间判断：至少有一枚令牌时返回 true 并扣除一枚；不足一枚时返回 false，不消耗已有额度。不等待未来的令牌，失败调用也不能丢掉已经累计的小数额度或重复计算经过的时间。
4. **REQ-04 并发与隔离**：多个 goroutine 可以同时调用 `Allow`，没有数据竞争或超额放行；效果等价于某个符合调用先后关系的串行顺序。不同实例的额度互不影响。

补充是按经过的时间连续计算，不是每过一个整秒才统一发放。恰好达到一枚时必须允许通过；时间没有推进时不能凭空增加令牌。

## 实现约束

- **CHECK-01**：只用标准库；所有时间判断使用传入的时钟，不启动后台 goroutine，不通过 `Sleep`、忙等或定时器等待令牌。通过源码检查和竞态检测验收。
- **CHECK-02**：`New`、`Allow` 的时间和每个实例的额外空间均为 `O(1)`，不计同步等待和时钟调用，不能按请求数量积累历史记录。通过源码注释和代码 Review 检查。

## 示例

创建 `rate = 2`、`burst = 2` 的限流器，假时钟从 `t0` 开始：

| 操作 | 结果 |
| --- | --- |
| t0 连续调用 3 次 `Allow()` | `true`、`true`、`false` |
| 推进到 t0 + 250 毫秒，再调用 | `false`，只补充了半枚 |
| 推进到 t0 + 500 毫秒，再调用 | `true`，半枚额度没有因上次失败丢失 |
| 同一时刻再调用 | `false`，刚才已经消耗一枚 |
| 推进到 t0 + 10 秒，连续调用 3 次 | `true`、`true`、`false`，最多只能存两枚 |

表中的额度只用于解释，不要求提供查询令牌数量的接口。

## 验证要点

以下场景均需验证；测试只使用公开接口，临时测试文件不提交到仓库。

| 场景 | 对应要求 | 操作与期望 |
| --- | --- | --- |
| TC-01 创建与校验 | REQ-01 | rate、burst 分别传入 0、负数时 panic；合法参数 1、10,000 可创建。`New(1, 1, nil)` 第一次 Allow 为 true |
| TC-02 初始额度 | REQ-01、03 | 固定时钟，burst 为 1、3、10,000 时，连续 burst 次均为 true，后续反复调用均为 false |
| TC-03 小数累计 | REQ-02、03 | rate 为 2、burst 为 1，耗尽后每推进 125 毫秒调用一次；前 3 次为 false，第 4 次为 true，同一时刻再次调用为 false |
| TC-04 满桶上限 | REQ-02、03 | rate 为 2、burst 为 2，从创建开始空闲 10 秒，固定该时刻连续调用只允许 2 次；再过 250 毫秒仍拒绝，再过 250 毫秒允许一次，多余空闲额度没有保留 |
| TC-05 混合时间序列 | REQ-02、03 | 按完整示例执行，逐次返回值一致；同一时刻的拒绝调用不会改变下次补充结果 |
| TC-06 并发放行 | REQ-03、04 | 固定时钟，burst 为 10，100 个 goroutine 同时调用，恰好 10 个 true；全部结束后推进 500 毫秒，rate 为 4 时下一批恰好 2 个 true |
| TC-07 实例隔离与规模 | REQ-01～04 | 耗尽一个实例后，另一个实例仍能使用初始额度；固定时间累计调用 100,000 次，总放行数恰好为 burst，竞态检测无报告 |

假时钟只在上一批操作全部结束后推进，并发操作期间固定时间；不用真实等待或 `Sleep` 验证速率。时间边界用可精确表示的补充量，例如 125、250、500 毫秒与上述整数 rate，不围绕浮点舍入误差构造临界用例。并发测试加宽松超时，不规定哪些 goroutine 获准。
