# Experiment 9：简易发布订阅

> 类型：并发组件 · 语言：Go 1.22+ · 难度：入门进阶 · 建议时长：90～120 分钟
> 规模：核心实现与临时验证合计以 500 行以内为参考，不按行数验收。

实现一个进程内的发布订阅组件：按 topic 广播整数，每个订阅者有自己的缓冲区。重点练习并发访问，以及发送、取消和关闭之间的协调。

基础版支持订阅、发布、取消订阅和关闭；慢订阅者缓冲满时丢弃新消息。不要求回调、消息重试、历史回放、持久化、网络通信或通配 topic。

## 接口

```go
package pubsub

type PubSub struct {
    // 内部结构自行设计
}

var ErrInvalidBuffer error
var ErrClosed error

func New() *PubSub
func (p *PubSub) Subscribe(topic string, buffer int) (<-chan int, func(), error)
func (p *PubSub) Publish(topic string, value int) error
func (p *PubSub) Close()
```

- 两个公开错误必须是不同的非 nil 错误；调用者用 `errors.Is` 判断，不约束错误文案。公共接口保持不变。
- `topic` 是按字符串精确匹配的名称，允许空字符串，区分大小写，不裁剪空格；`value` 可以是任意 `int`。
- `buffer` 合法范围为 1～10,000；大于 10,000 的输入不要求处理。验证规模：累计最多 10,000 次订阅、100,000 次发布，同时有效订阅的缓冲容量总和最多 100,000。
- 实例只通过 `New` 创建；零值、nil 接收者、复制 `PubSub` 本身超出范围。订阅通道由组件关闭，调用者只负责接收；多个接收者共享同一订阅时共同消费消息。

## 要求

1. **REQ-01 创建与订阅**：`New` 返回独立、未关闭且没有订阅的实例。合法订阅返回一个非 nil 的接收通道、非 nil 的取消函数和 nil 错误；通道初始为空，容量等于 `buffer`。同一 topic 可以重复订阅，各自独立。
2. **REQ-02 订阅错误**：`buffer <= 0` 返回 `(nil, nil, ErrInvalidBuffer)`，即使实例已关闭也优先返回这个错误；否则关闭后的订阅返回 `(nil, nil, ErrClosed)`。失败不新增或改变订阅。
3. **REQ-03 发布**：未关闭时，`Publish` 向该 topic 的每个有效订阅各尝试交付一次，不影响其他 topic；没有订阅也返回 nil。发布返回前完成本次交付或丢弃决定。订阅不会补收订阅之前的消息。
4. **REQ-04 缓冲与顺序**：每个订阅在交付时有空位就接收新值，满了只丢弃这个新值，不覆盖或取走已排队的值。各订阅独立判断；满的订阅不能阻止其他订阅接收，也不能让发布等待消费者。未丢弃的值在该通道中按交付顺序接收；顺序调用的发布保持先后次序。
5. **REQ-05 取消**：取消函数移除自己的订阅并关闭其通道，不影响其他订阅。同一取消函数可重复或并发调用，均正常返回。取消返回后不会再向该通道放入值；已有缓冲值仍可按顺序排空，之后接收恒为 `(0, false)`。同 topic 可再次创建新订阅。
6. **REQ-06 关闭**：`Close` 关闭实例和全部有效订阅，不等待消费者，也不清空缓冲；返回时这些通道都已关闭，排空规则同 REQ-05。重复或并发关闭、关闭后调用取消函数均正常返回。关闭后的发布返回 `ErrClosed`，不交付消息。
7. **REQ-07 并发安全**：所有公开操作、取消函数与消费者接收都可并发使用，不得数据竞争、重复交付或向已关闭通道发送而 panic；不同实例的订阅和关闭状态互不影响。

并发调用不按 goroutine 启动顺序排序。订阅、取消和关闭各有一个发生在调用与返回之间的生效点；发布也在此期间检查实例是否关闭：检查时已关闭就返回 `ErrClosed`，且本次没有任何交付。

检查时未关闭的发布返回 nil，但与它重叠的 `Subscribe` 调用创建的新订阅可以收到或收不到本次消息；对每个订阅，交付与取消/关闭按各自生效先后处理，先失效就不再交付。发布可以在不同订阅上分别作决定，不要求一次广播对全部订阅同时生效。并发发布在不同订阅上的顺序可以不同；所有未重叠的调用仍须遵守上述顺序规则。

## 实现约束

- **CHECK-01**：只使用标准库，允许内置 channel 和 `sync`；禁止第三方依赖、外部服务以及用 `unsafe` 绕过类型限制。通过源码检查验收。
- **CHECK-02**：组件内部不创建 goroutine；不能忙等或用 `time.Sleep` 轮询，也不能等待消费者接收后才结束发布、取消或关闭。锁竞争等待允许。通过代码 Review 验收。
- **CHECK-03**：设 `s` 为当前有效订阅数、`t` 为目标 topic 的有效订阅数、`B` 为有效订阅的缓冲容量总和。订阅的缓冲分配开销最多 `O(buffer)`，其余登记与取消的平均开销为 `O(1)`；发布为 `O(t+1)`，关闭为 `O(s+1)`。组件空间按 `s`、`B` 的历史峰值计算为 `O(s+B+1)`，不累计保留失效订阅或历史消息；调用者仍持有的已关闭通道与取消函数占用另计。忽略字符串哈希、锁等待和运行时调度开销，通过设计说明与代码 Review 验收。

## 示例

以下操作按顺序执行，期间没有其他消费者：

```go
p := New()
a, cancelA, _ := p.Subscribe("news", 1)
b, _, _ := p.Subscribe("news", 2)
p.Publish("news", 10) // nil：a、b 各收到 10
p.Publish("news", 20) // nil：a 满了丢弃 20，b 收到 20
cancelA()             // a 关闭，已有的 10 保留
va, oka := <-a        // 10, true
_, doneA := <-a       // 0, false
p.Close()            // b 关闭，已有的 10、20 保留
vb1, okb1 := <-b      // 10, true
vb2, okb2 := <-b      // 20, true
_, doneB := <-b       // 0, false
err := p.Publish("news", 30) // ErrClosed
```

## 验证要点

以下场景均为必测，只通过公开接口和返回通道验证；测试文件只放在仓库外的临时副本。

| 场景 | 对应要求 | 操作与精确期望 |
| --- | --- | --- |
| TC-01 创建与输入 | REQ-01、02 | 容量 1、10,000 的新订阅非 nil、为空且 `cap` 相等；容量 0、-1 返回 `(nil, nil, ErrInvalidBuffer)`，已有订阅仍能收值 |
| TC-02 匹配与独立订阅 | REQ-01、03 | 发布无订阅的 topic 返回 nil；分别订阅 `""`、`"news"`、`"News"`、`"news "`，只精确匹配者收到；同 topic 两次订阅各收到一次，之后新订阅不含旧消息 |
| TC-03 丢弃与保序 | REQ-03、04 | 给容量 1、2 的同 topic 订阅依次发布 10、20；发布均返回 nil，前者只取出 10，后者依次取出 10、20；排空后再发布，两者都能收到新值。0、负数、重复值及 int 边界值原样保留 |
| TC-04 取消与重订阅 | REQ-03、05 | 取消空订阅后接收为 `(0, false)`；取消有缓冲值的订阅后原值可排空；重复取消正常，后续发布只到其他有效订阅，新订阅可以正常接收 |
| TC-05 关闭与错误 | REQ-02、05、06 | 关闭空实例及含空/非空订阅的实例；所有通道排空后都返回 `(0, false)`。重复关闭、取消均正常；合法订阅返回 `(nil, nil, ErrClosed)`，非法容量仍优先报 `ErrInvalidBuffer`，发布报 `ErrClosed` 且无新值 |
| TC-06 并发发布 | REQ-03、04、07 | 4 个发布者各顺序发布 100 个不同整数，两个订阅容量均为 400，期间不接收；发布全部返回 nil，关闭后每个订阅各收到完整 400 个值，无重复，且各发布者自己的顺序保持 |
| TC-07 取消与关闭竞争 | REQ-02、05～07 | 对同实例并发执行合法订阅、发布互不重复的值、重复取消和关闭，等待全部结束；订阅只能成功或返回 `(nil, nil, ErrClosed)`，发布只能返回 nil 或 `ErrClosed`，后者消息不得收到；所有成功订阅最终可排空并结束，无 panic 或数据竞争。成功发布与关闭重叠时允许消息未交付 |
| TC-08 隔离与规模 | REQ-01、03～07 | 关闭实例 A 不影响 B 收值；一个实例累计订阅并取消 10,000 次，全部通道关闭；另一个实例向同一有效订阅发布并逐次取出 100,000 次，次数、值和顺序均一致，最后关闭可结束接收 |

并发测试用同步信号协调，不用固定 `Sleep` 猜调度；用无人接收的已知缓冲容量确定满/空状态。等待加宽松超时，失败时关闭实例并清理 goroutine；不把“goroutine 已启动”当成操作已经生效。竞争测试接受题面允许的结果，并用有效断言检查收到的值及关闭状态。

实现放在 `experiment/experiment9/code/pubsub.go`，包名 `pubsub`；module 固定为 `traditionalcoding-gym/experiment9`，配置放在 `experiment/experiment9/code/go.mod`。只交付源码、README 和必要构建配置，不提交测试、评测脚本或编译产物。

```sh
mkdir -p experiment/experiment9/code
cd experiment/experiment9/code
```

写完后在上述 `code/` 中运行 `gofmt -w pubsub.go`，`gofmt -l pubsub.go` 应无输出。把 `code/` 复制到仓库外的新临时目录，在副本中准备验证测试，以该副本为工作目录运行：
