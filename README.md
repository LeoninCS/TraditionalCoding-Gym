# 背景
我丧失了编程能力。
# 想法
我计划每隔一段时间会有一个小的0-500行的古法编程小训练，即定义一个小的需求，或许只是一个算法，或许是一个函数，或许是一个小的工具，亦或一个小型项目，然后去纯手工实现（即古法编程完全不依赖各种AI），当然可能会让AI来Review，或者让AI选题（或许有朋友愿意一起Review或者选题那更好了），那就有了乐趣。毕竟我这个本意也不是为了说是远离AI，时代在进步，科技在发展，远离AI岂不是自己在主动脱离时代，相反，我是一个极度依赖AI的AI Native人，我将AI融入了我的工作流，融入了我的生活，甚至我每天会和AI聊很久来复盘反思我的一天，我也会听取AI一些建议，也会让AI帮我做一些决策等，AI确实极大的提高了我的生产效率，也让我一个天赋比较平庸的人和一些天才的差距得以拉小。所以我还是很感谢AI的，也很希望AI可以发展的越来越强。
# 目的
一方面是为了体验编程的乐趣，现在天天和LLM对话，有点点空虚。说是-提效，但每天也很忙，接触的信息量极多，认知负载极重，并没有因为AI提效而轻松，反而更累，累到啥都不想看，每天Review AI的方案是真的累，有时信息密度极低，真的不想看一眼，或许古法编程反而能让我平静下来。 

另一方面，AI时代的一个重要能力就是自己的taste，即你需要从AI的回复中判断出什么是好的，那首先你需要知道什么是好的，而知道什么是好的路径即你有丰富的经验，有自己的能力，这样才能有自己的判断力，一个暴论就是如果你走的每一步都很完美，那你大概率会很顺利，这当然是好的，这证明你已经有了判断力，可以说很有天赋了。但对于普通人，不可能每一步都完美，甚至刚开始是坎坷的，但是会在失败中逐渐积累经验，慢慢使路变得好走，慢慢提升判断力。但AI总会生成一个完美的答案，帮我们避开了可能的错误，让我们没有办法积累经验，这样我们慢慢就会成为一个完全依赖于AI的人，也很难有自己的taste，所以需要古法编程来训练。  

为什么需要古法编程呢，程序员重要的是主动发现问题，产生需求或者理解需求，以及不同人员的对接，以及方案的选型和设计，根据现实场景决策一些trade off，以及后续的review来确保可行，编码只是其中很小的一部分，是不是在AI时代或者说Agent时代没有这个必要了呢，相反，我觉得异常有必要，因为对于后面的review环节，你需要有自己的编码范式，才会看出AI哪里写的冗余，哪里写的啰嗦，哪里写的过于复杂，所以这个是需要你有代码能力的，其次，review的过程其实是边界的检查和一些case的验证，那你如何知道这个边界和心里有这个case呢，这个还是依赖于你实际踩过的坑，否则很难去理解。故采用古法编程训练。
